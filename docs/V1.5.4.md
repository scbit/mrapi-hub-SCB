# MR API HUB v1.5.5 — Media + Smart Scroll + Multi-line

## Bandeja / WhatsApp

### Media usable
- Los adjuntos entrantes de Twilio se resuelven bajo demanda.
- Audio: botón que carga un reproductor HTML5.
- Imágenes: preview clickeable.
- PDF/otros: botón Abrir.
- Al primer acceso, el archivo se copia al bucket del tenant y se guarda `gcsPath` en el mensaje; posteriores accesos renuevan una signed URL.
- Esto evita depender para siempre de URLs protegidas/temporales de Twilio.

### Scroll inteligente
- Inbox Live ya no fuerza el scroll al final cada ~2 s.
- Si el usuario está cerca del final, sigue el chat automáticamente.
- Si está leyendo mensajes viejos, mantiene la posición.
- Si llegan mensajes mientras está arriba, aparece `N mensajes nuevos ↓`.
- El polling no rerenderiza si solo recibió nuevamente el mismo documento por la ventana de solapamiento.

### Multi-line
- Botón `Líneas` en el encabezado del chat.
- Descubre conversaciones del mismo `waFrom` recibidas por otros números/líneas.
- `Vincular todas` conecta esas conversaciones mediante `duplicateConversationIds` y `linkedLineIds`.
- La conversación puede elegir `preferredLineId` para responder por una línea determinada.
- El envío de texto, archivo y template respeta `preferredLineId` antes de la línea de ingreso original.

## Endpoints nuevos
- `GET /api/inbox/conversations/:id/lines`
- `POST /api/inbox/conversations/:id/lines/link-all`
- `POST /api/inbox/conversations/:id/lines/preferred`
- `GET /api/inbox/conversations/:id/messages/:messageId/media/:index`

## Reads
- Media: no genera lecturas mientras no se abre/carga el adjunto. Primer acceso: 1 read + 1 write si hay que copiar desde Twilio. Accesos posteriores: 1 read para renovar URL firmada.
- Líneas: se consulta solo al abrir el administrador de líneas, con `where(waFrom == ...)` y límite 20.
- Inbox Live mantiene el esquema incremental de v1.5.3.
